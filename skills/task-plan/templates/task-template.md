## 任务章节

```markdown
### 阶段一：{阶段名称}

### Task-001：{任务标题}

描述：{任务目标、实现内容}

验收标准：
- [ ] {验收条件1}
- [ ] {验收条件2}
- [ ] {边界情况}
- [ ] {性能/安全要求}

验证步骤：
- [ ] 单元测试：`{测试命令}`
- [ ] 构建：`{构建命令}`
- [ ] 手动验证：{检查步骤}
- [ ] 代码审查：{审查内容}

关联需求：{需求摘要}

依赖关系：
- 前置：{前置任务ID，或"无"}
- 后置：{依赖任务ID}
- 并行：{可并行任务}

工时估算：{X} 人天
- 基础：{X} 人天（{XS/S/M/L}）
- 缓冲：{X} 人天（{风险类型}）
- 总计：{X} 人天

任务大小：{XS/S/M/L/XL}
- 文件数量：{X} 个
- 代码量估算：{X} 行
- 依赖数量：{X} 个
- 评估依据：见 ../references/complexity-definition.md

技术风险：{无/低/中/高}
- 类型：{技术/依赖/业务}
- 描述：{风险详情}
- 等级：{低/中/高}
- 缓冲系数：{X}%
- 应对：{降低风险方法}

涉及的文件：
- 新增：
  - `{文件路径}` - {用途}
- 修改：
  - `{文件路径}` - {修改内容}
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| 描述 | 任务目标和实现内容 |
| 验收标准 | 具体可测试条件，每条对应一个可验证的结果 |
| 验证步骤 | 测试命令、构建命令、手动检查步骤 |
| 关联需求 | 对应哪个需求或用户故事 |
| 依赖关系 | 前置任务（必须先完成）、后置任务（依赖本任务）、并行任务 |
| 工时估算 | 基础工时 + 缓冲工时 = 总工时 |
| 任务大小 | XS/S/M/L/XL，按文件数、代码量、依赖数综合评估 |
| 技术风险 | 风险类型、等级、缓冲系数、应对策略 |
| 文件 | 新增和修改的文件列表，附用途说明 |

**验收标准编写**：验收标准应具体可测试。例如"输入正确用户名密码后跳转到首页"优于"用户可以登录"。

**工时计算**：

```
缓冲工时 = 基础工时 × 缓冲系数 × 风险等级系数
总工时 = 基础工时 + 缓冲工时
```

风险类型、缓冲系数、风险等级系数详见 `../references/risk-classification.md`。

## 检查点

```markdown
### 检查点：{阶段名称}完成

检查项：
- [ ] {技术验收}
- [ ] {功能验收}
- [ ] 人工审查：{审查内容}

下一步：
- {继续条件}
- {确认问题}
```

**设置时机**：
- 每个阶段结束后
- 关键技术决策后
- 高风险任务完成后

## 风险和应对措施

```markdown
## 风险和应对措施

| 风险 | 类型 | 等级 | 影响 | 应对措施 |
|------|------|------|------|---------|
| {风险描述} | {技术/依赖/业务} | {低/中/高} | {影响范围} | {应对策略} |
```

**风险类型**：
- 技术风险：新技术、复杂算法、性能优化、安全加密
- 依赖风险：第三方库、外部接口、团队协作
- 业务风险：需求不确定、边界情况、用户体验
