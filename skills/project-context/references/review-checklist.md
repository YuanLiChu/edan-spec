# Project Context 评审清单

## 1. 完整性

- [ ] 本次模式和范围明确。
- [ ] L0/L1/L2/L3/L4 按用户需求生成；未请求层级有说明。
- [ ] 所有索引链接指向实际文件。
- [ ] 每个模块和业务流有职责/用途说明。
- [ ] 每张图有图例、证据表和已知盲区。

## 2. 正确性

- [ ] CodeGraph 版本、索引状态和覆盖语言来自实际命令。
- [ ] 所有 Verified 符号和路径存在。
- [ ] 调用边方向是 caller→callee。
- [ ] impact radius 没有被当成业务调用链。
- [ ] 搜索 score 没有被当成置信度。
- [ ] QML、Qt signal/slot、宏、回调、事件和生成代码缺口未伪装成 Verified。

## 3. 可读性

- [ ] L0 为 10-30 节点。
- [ ] 每张 L1 图 ≤25 节点。
- [ ] 每张 L2 图为 8-20 节点且只描述一个场景。
- [ ] 图中节点使用“工程职责 + 代码符号”。
- [ ] 所有重要边有具体关系语义和 Evidence ID。
- [ ] 完整路径放在证据表，不塞入节点。
- [ ] 图的阅读入口和边界在图前说明。

## 4. 一致性

- [ ] L0 与 L1 跨模块关系一致；冲突时已按证据修正 L0。
- [ ] L2 核心入口可回链到 L1。
- [ ] L2 流程专属/跨模块节点有明确归属，不被强制塞入 L1。
- [ ] Evidence ID 在单文档内唯一。
- [ ] 证据状态只使用 `Verified`、`Graph-Heuristic`、`Inferred`、`Unknown`。

## 5. 闭环

- [ ] 所有 CRITICAL 已修复。
- [ ] 所有 IMPORTANT 已修复或有用户明确接受。
- [ ] Unknown 有具体人工确认或运行时验证建议。
- [ ] 修复后重新运行了相关验证。
- [ ] 完成报告只声称实际执行和验证过的事项。
