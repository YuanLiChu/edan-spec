# 拆分策略

## 垂直切分（推荐）

每个增量交付一个完整的功能链路，端到端可用：

```
增量 1：创建任务（数据模型 + API + 界面）→ 可创建
增量 2：列出任务（查询接口 + API + 列表）→ 可查看
增量 3：更新任务（编辑表单 + API + 校验）→ 可修改
增量 4：删除任务（删除接口 + API + 确认）→ 完整 CRUD
```

## 契约优先

前后端并行开发时采用：

```
增量 1：定义 API 契约（类型声明、接口规范）
增量 2：按契约实现后端 + 前端 Mock 数据
增量 3：联调集成
```

## 风险优先

优先验证最高风险的部分：

```
增量 1：验证 WebSocket 连通性 → 不通过则及时止损
增量 2：在已验证的连接上构建业务逻辑
增量 3：实现离线支持与重连机制
```

## 增量标准

| 指标 | 建议 |
|------|------|
| 代码行数 | ≤100 行/增量 |
| 涉及文件 | ≤3 个/增量 |
| 验收标准 | 1–2 条/增量 |

每个增量完成后：
- [ ] 测试套件全部通过
- [ ] 构建成功
- [ ] 已提交
