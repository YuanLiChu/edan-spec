# Qt/C++ 嵌入式项目技术参考

> 供 create-spec / design-review 决策确认。目标栈：**C++ + Qt 6（Embedded Linux / 无桌面环境）**。桌面见 [platform-qt.md](platform-qt.md)。

---

## 一、架构模式

### 架构对比

| 架构 | 实时性 | 复杂度 | 适用场景 |
|-----|--------|--------|---------|
| **前后台 + Qt 事件循环** | 低–中 | 低 | 单进程 HMI，无硬实时 |
| **分层：HMI / 应用 / 设备适配 / BSP** | 中 | 中 | 默认。UI 与设备协议隔离 |
| **HMI 进程 + 实时/采集进程** | 高 | 高 | 采集/控制有周期与看门狗要求 |
| **RTOS 无 Qt** | 最高 | 中 | 硬实时 MCU；**不在本 skill 的 Qt 范围内** |

**默认推荐**：Linux 用户态 Qt HMI + 独立设备/协议进程或线程。硬实时不放进 Qt 事件循环。

### 进程与线程切分

| 职责 | 建议载体 | 说明 |
|------|---------|------|
| 界面、绑定、用户输入 | GUI 线程 | 永不做设备等待 |
| 协议解析、重连、队列 | `QObject` worker 线程或独立进程 | 看门狗可杀进程 |
| 周期采样、驱动 | 独立进程 / 内核 / MCU | 用共享内存、Unix socket、CAN 与 HMI 通信 |
| 持久化 | 异步写，主线程只发命令 | 掉电安全另见存储 |

## 二、技术栈

### 技术选型

| 决策项 | 选项 | 推荐 | 说明 |
|--------|------|------|------|
| 语言 | C++17/20，局部 C | **C++17 下限，能上 C++20 则上** | sysroot 编译器决定上限 |
| UI | Qt Quick、Widgets、EGLFS 全屏 | **嵌入式触控优先 Qt Quick** | 无桌面环境用 EGLFS 或 linuxfb |
| 操作系统 | Embedded Linux、Yocto、Buildroot | **Yocto 或已有 BSP** | 版本钉死 |
| 显示 QPA | eglfs、linuxfb、wayland | **有 GPU：eglfs 或 wayland；无 GPU：linuxfb** | 必须在目标板验证 |
| 构建 | CMake + 交叉 sysroot | **CMake + Qt 为该 BSP 构建的套件** | 禁止用桌面 Qt 冒充目标 |
| 设备通信 | UART、TCP、CAN、共享内存 | **按总线；协议层不进 QML** | |
| 存储 | SQLite、幂等日志文件、原始分区 | **掉电场景验证 fsync/WAL** | |
| 测试 | 主机 GTest + 目标集成 | **逻辑在主机测；I/O 用 Fake** | HIL 单列任务 |

### 推荐组合

| 项目规模 | 技术栈 |
|---------|--------|
| 小型面板 | C++ + Qt Quick + EGLFS + 单进程 worker 线程 |
| 中型设备 HMI | C++20 + 分层 + Quick + 设备进程 + SQLite |
| 大型 | HMI 与实时域分进程、协议版本化、远程日志、OTA |

## 三、交叉构建与版本约束

| 决策项 | 推荐 | 说明 |
|--------|------|------|
| Qt | 与 BSP **同一套** Qt 6.x | 桌面 6.8 不能假设板端 6.5 API 全可用 |
| 工具链 | 厂商/Yocto SDK | `CMAKE_TOOLCHAIN_FILE` 入库 |
| sysroot | 版本化、CI 缓存 | 禁止每人本地手改 |
| OpenGL/ES | 与 GPU 驱动匹配 | 记录 GLES 版本 |
| 异常与 RTTI | 与 Qt 构建选项一致 | Qt 通常需要 RTTI/异常；关掉必须全栈一致 |

### 检查清单

1. [ ] 交叉 CMake 能在干净环境配置（toolchain + Qt 路径）
2. [ ] 目标 `qt.conf` / 插件路径正确（eglfs、imageformats）
3. [ ] 未把 x86_64 的 Qt 插件打进 ARM 包
4. [ ] 启动参数明确：`QT_QPA_PLATFORM`、`QT_QPA_EGLFS_*`、旋转、输入设备
5. [ ] 内存预算：RSS 峰值、GPU 纹理、启动时间有指标
6. [ ] 看门狗：HMI 无响应可重启，不拖死采集进程

## 四、嵌入式 Qt 特有约束

- [必须]  启动路径无显示器时仍能跑无头诊断构建（CI）
- [必须]  输入设备（触摸校准、多点、实体键）在适配层，不散落 QML
- [必须]  分辨率与 DPI 策略写入 design.md（固定分辨率 vs 缩放）
- [必须]  日志环形缓冲，防止 `/var` 写满
- [必须]  时间跳变（无 RTC、NTP 回拨）不破坏协议序号与文件名
- [禁止]  在设备上依赖 `desktop` 服务（DBus 会话、字体服务未裁剪时要自备字体）
- [禁止]  热路径分配大 `QImage`/`QQuickItem` 而不复用
- [禁止]  用 `QProcess` 调未固定路径的 shell 拼用户输入（命令注入）

### 实时与 Qt

Qt 事件循环 **不是** 硬实时。周期 ≤ 10ms 的控制环不要放在槽函数里靠 `QTimer` 凑。

| 需求 | 做法 |
|------|------|
| UI 刷新 16–33ms | GUI 线程 + 双缓冲数据 |
| 协议超时 50–200ms | worker 线程 `QTimer` 或 posix timer |
| 控制环 < 10ms | 非 Qt 进程/线程，共享内存投递快照给 HMI |

## 五、测试、覆盖率与板上验证

| 层级 | 在哪跑 | 命令/方式 |
|------|--------|----------|
| 单元 | 主机 | `ctest -R unit`，Fake 设备 |
| 协议 | 主机 | 录制报文回放 |
| HMI 冒烟 | 主机 offscreen 或目标 | QTest / 截图对比（可选） |
| 覆盖率 | 主机 GCC/Clang | gcov/llvm-cov，阈值同桌面 |
| HIL | 目标板 | 单独流水线，缺硬件 skip 并标记 |

覆盖率基线仍为行 80% / 分支 70%；与硬件强耦合的适配器可列入豁免表，但必须在 design.md 列出文件名。

## 六、安全要点（设备）

- 调试口（ADB 类、telnet、无认证串口 shell）不得出现在发布镜像
- 本地服务绑定 `127.0.0.1` 或 Unix socket 权限；禁止 `0.0.0.0` 无鉴权
- OTA 验签；失败可回滚分区
- 日志与崩溃转储不含密钥、完整个人数据
- 安全启动链与 rootfs 只读为产品决策，须在 design 记录是否采用
