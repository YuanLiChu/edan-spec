# 常见借口与反驳

Agent 容易给自己找的借口。看到这些说辞时，对照真相打住。

## "太简单，不用"

| 说辞 | 真相 |
|------|------|
| "这个简单，不用文档" | 两行验收标准也是文档，不能没有 |
| "改动小，不用审查/测试" | 小改动最难回滚，最易漏测 |
| "函数简单，不用测试" | 空值、类型转换的 bug 全在"简单"代码里 |
| "代码简单，不用审查" | 最简单的代码反而最没人仔细看 |

## "后面再补"

| 说辞 | 真相 |
|------|------|
| "后面再补测试/文档/安全" | 没有"后面"。现在不做 = 永远不会做 |
| "先出代码再补文档" | 那不是方案，是回忆录。方案的价值是写之前想清楚 |
| "功能做完再管性能/安全" | N+1 查询越堆越多。事后补安全比内置贵 10 倍 |
| "先随便提交，后面 squash" | Squash 能修消息，修不了丢失的变更意图 |

## "差不多就行"

| 说辞 | 真相 |
|------|------|
| "79% 和 80% 差不多" | 差 1% = 有代码路径在生产裸奔 |
| "代码能跑就行" | 能跑 ≠ 正确。第一个异常输入就崩 |
| "跳过 hook/门禁吧" | Hook 误报修 hook，不是跳过。跳过一次，次次想跳 |
| "优化了一点，应该有效" | 没测量 = 不知道是改善还是劣化 |

## "我清楚，不用确认"

| 说辞 | 真相 |
|------|------|
| "方案我清楚，不用确认" | 等 5 分钟确认比改 5 小时代码划算 |
| "方案说 A 代码是 B，我选 A" | 冲突时别自己选，报告、给选项、等决策 |
| "我记得上次做了啥" | 记忆不可靠。会话会压缩。从文件和 git 恢复 |
| "需求很清楚，不用确认" | 一行 PLAN 省一小时返工。让用户有机会纠偏 |

## "效率优先"（反而更慢）

| 说辞 | 真相 |
|------|------|
| "同时做多件事效率高" | 上下文切换是效率杀手。一次一个增量 |
| "一次性全生成，快" | 上下文膨胀，每章质量跳水。逐章 > 堆量 |
| "两个小改动一起做" | 出问题分不清谁引入的。一个增量一件事 |
| "没时间定位了，快速修" | 快修 = 3 倍时间返工。多花 5 分钟定位，省 30 分钟 |
| "应该不慢，不用测" | "应该"是猜的，测量才是证据 |

## "这个场景特殊"

| 说辞 | 真相 |
|------|------|
| "内部接口，不用安全检查" | 内网被攻破，内部接口就是敞开的 |
| "只是原型，不用太安全" | 原型会变生产。被遗忘的测试端点 = 最大后门 |
| "不影响用户，不用审查" | 内部质量影响所有后续开发者的理解成本 |
| "没人会攻击我" | 自动化扫描器不挑目标。隐匿 ≠ 安全 |
