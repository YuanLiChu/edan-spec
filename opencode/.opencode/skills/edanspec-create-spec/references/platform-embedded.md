# 嵌入式项目技术参考

> 供design-review 的阶段一决策确认时参考。

---

## 一、架构模式

### 架构对比

| 架构 | 实时性 | 复杂度 | 适用场景 |
|-----|--------|--------|---------|
| **前后台系统** | 低 | 低 | 简单控制（LED、传感器） |
| **RTOS** | 高 | 中 | 实时多任务（工控、医疗） |
| **分层架构** | 中 | 高 | 大型项目（车载、智能家居） |

**前后台系统** — main 循环（前台）+ 中断（后台）。结构简单、内存占用小，但实时性差、扩展性弱。

**RTOS** — 基于实时操作系统的多任务调度（FreeRTOS / RT-Thread）。任务间通过队列/信号量通信。实时性好，支持并发。学习成本较高。

**分层架构** — BSP（板级支持）→ HAL（硬件抽象）→ Middleware → Application。硬件与应用解耦，代码可移植性好。分层引入额外抽象层，代码量多。

### 选型建议

| 项目规模 | 推荐架构 |
|---------|---------|
| 简单控制（单功能） | 前后台系统 |
| 多任务 / 实时性要求 | RTOS（FreeRTOS / RT-Thread） |
| 大型 / 需硬件抽象 | 分层架构 |

## 二、技术栈

### 技术选型

| 决策项 | 选项 | 推荐 | 说明 |
|--------|------|------|------|
| 编程语言 | C、C++、Rust | **C**（嵌入式主流）、**C++**（大型项目） | Rust 安全性好但生态尚不成熟 |
| 操作系统 | 前后台、FreeRTOS、RT-Thread、Linux | **FreeRTOS**（轻量）、**RT-Thread**（国内生态）、**Linux**（复杂应用） | 实时选 RTOS，复杂应用选 Linux |
| 开发框架 | HAL、Arduino、PlatformIO | **HAL**（底层）、**Arduino**（快速原型） | HAL 贴近硬件，Arduino 生态丰富 |
| 通信协议 | UART、SPI、I2C、CAN、MQTT | **MQTT**（物联网）、**CAN**（车载） | 按总线类型选择 |
| 测试 | 单元测试、HIL（硬件在环） | **单元测试**（逻辑层）、**HIL**（集成层） | |

### 推荐组合

| 项目规模 | 技术栈 |
|---------|--------|
| 小型 | C + 前后台 + HAL |
| 中型 | C + FreeRTOS + MQTT |
| 大型 | C/C++ + 分层架构 + Linux + MQTT |
